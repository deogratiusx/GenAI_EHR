# План финального прогона и анализа

Зафиксирован 25.10.2026 до получения результатов. Сценарии прогона — `scripts/final_api.sh` и
`scripts/final_local.sh`. Анализ — `python -m ehr_agent.eval.stats`.

## Состав

- **Вопросы.** Разреженная стратифицированная выборка: один вопрос на ячейку «набор × пациент × категория»,
  перефразировки L2/L3 идут за своим исходным вопросом. Всего 105 вопросов: 95 точечных и 10 сводок.
  Набор `dev` не используется.
- **Политика норм:** `layered` (бланк → пороги клинических рекомендаций → NHANES → каталог). Эталоны —
  `data/questions_layered.jsonl`.
- **Температура 0, один прогон.** Отдельно — три прогона при T = 0.5 основной системы на наборе `test` для
  обеих моделей GigaChat, чтобы оценить разброс от прогона к прогону.
- **Модели и системы:**

| Модель | Точечные вопросы | Сводки |
|---|---|---|
| GigaChat Max | tools, tools_routed, tools_plain, code, record; record_chunked на PDF и динамике | tools, report, report_nocheck, record / record_chunked |
| GigaChat Lite | то же + tools_compact, tools_prefetch | то же |
| Qwen3.5-4B | tools, code; record на `test`; record_chunked на 6 PDF-вопросах | tools, report |
| Med-Qwen-4B | tools | tools, report |

## Гипотезы и сравнения

Все сравнения парные: одни и те же вопросы. Метрика — верность (0–1) по типу эталона; для сводок также
critical recall. Эпизоды с `context_overflow` исключаются из пары (N/A).

| # | Гипотеза | Сравнение | Модели |
|---|---|---|---|
| H1a | Инструменты лучше интерпретатора кода | tools vs code | все, где есть оба |
| H1b | Инструменты не хуже всей карты в контексте при меньшей цене | tools vs record (таблицы), tools vs record_chunked (PDF) | GigaChat, Qwen |
| H1c | Обвязка (проверки и починка формата) помогает | tools vs tools_plain | GigaChat |
| H2a | Досье и схема отчёта повышают полноту сводок | report vs tools, по чек-листу и critical recall | все |
| H2b | Проверки полноты и вердиктов добавляют к досье | report vs report_nocheck | GigaChat |
| H3 | Медицинское дообучение той же базы не даёт выигрыша | Med-Qwen vs Qwen (tools) | — |
| H4 | Лёгкая локальная модель с инструментами сопоставима с крупной облачной | Qwen vs Max (tools) | — |

- **Тест:** парный перестановочный (sign-flip) тест разности средних, 10 000 перестановок, двусторонний.
- **ДИ:** 95 % парный бутстреп разности.
- **Множественные сравнения:** поправка Холма по всему семейству H1–H4 сразу.
- **Абляции** (tools_routed, tools_compact, tools_prefetch) — описательные: ДИ без проверки гипотез.

## Ограничения, известные заранее

- **Эталоны не слепые.** Вопросы написаны автором инструментов. Наборы `trend` и `report` построены по данным
  перед прогоном. Эталон `report` — черновой (пункты `must_mention` досье) и измеряет полноту относительно
  собственного досье, а не клиническую истину. Независимую оценку дают только 6 ручных чек-листов сводок.
- **Отчётные системы настраивались на тех же 10 сводных вопросах** (смоук-прогоны). Результат H2 — оценка
  на обучающих данных, а не на отложенных.
- **Выборка маленькая:** 6 чекапов и 6 историй болезни. Мощности хватает только для крупных эффектов.
- **Автоматический оценщик проверяется вручную** на стратифицированной выборке ответов (`eval/audit.py`);
  доля совпадений публикуется.
