Anatomy of one episode

The model chooses and phrases; code retrieves, judges and checks

1 · Model → call

Question: “Какой уровень ЛПНП?” The model sees 12 tool specs and emits

get_lab(analyte="ЛПНП")

2 · Code → result

Synonyms resolve “ЛПНП” to LDL; the reference policy picks a layer; output is short JSON with row ids

id P003:r351 · 4.06 · flag H · ≤3.0 (guideline)

3 · Answer → checks

final_answer(answer, citations, status); the harness verifies ids, numbers and “not found” before accepting

“LDL 4.06 mmol/L, above target” [P003:r351]

Tool design ruleWhy (failure it prevents)
Typed arguments, JSON Schemavalidated before execution; an error is a repairable message, not a crash
Output budget, pagination3.5–24k characters per call; lists cut with next_offset, never mid-JSON (long-context loss)
Explicit emptinessfound=false with what was checked, so “not measured” is not confused with “not retrieved”
Every fact carries a row idanswers are verifiable; invented ids and numbers are caught by the harness
The example is a real episode of the main system on check-up P003. Budget: up to 4 tool calls; when it is spent, the final answer is forced.
